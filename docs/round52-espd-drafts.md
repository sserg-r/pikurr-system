### 1.1. A2: результат проверки

Временный контейнер `postgis/postgis:15-3.3` с уникальным именем (`r52-tmp-postgis-<pid>`) на координаторской машине; таблица `agrifields` создана вручную (в реальном маршруте её создаёт `ogr2ogr`); выполнен `create_assessment_schema.sql` (ошибок нет), затем вставка той же формы, что `save_db.py:53-58`:

```
ERROR:  null value in column "id" of relation "assessment" violates not-null constraint
DETAIL:  Failing row contains (1, null, 22120000550001, 2000, {"0": 0.5, "3": 0.5}, null, …, null).
```

Причина: `assessment.id INTEGER NOT NULL` без `DEFAULT` (`create_assessment_schema.sql`, `CREATE TABLE IF NOT EXISTS assessment`), вставка `id` не задаёт. DDL и код **не менялись**. Проверка предложения (только во временной БД): `CREATE SEQUENCE assessment_id_seq OWNED BY assessment.id; ALTER TABLE assessment ALTER COLUMN id SET DEFAULT nextval('assessment_id_seq');` — после этого вставка проходит (`INSERT 0 1`). Схема общая для ETL и витрины, поэтому решение — за пользователем (**ВОПРОС-7**): вариант 1 — добавить `DEFAULT nextval(...)` (`id SERIAL`) в DDL (импорт пакета на витрине задаёт `id` явно из GPKG — на него это не влияет); вариант 2 — ограничить ПМИ существующей ETL-базой (в которой `id` — `serial`). Контейнер удалён по имени (`docker rm -f`), остаточных контейнеров `r52-tmp*` нет.
