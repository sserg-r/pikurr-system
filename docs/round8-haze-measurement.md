# Раунд 8: дымка в исходных тайлах — измерение перед решением

См. `prompts/PROMPT_haze_measurement_round8.md` за полным ТЗ. Задача была
измерительной: ничего в пайплайне не менялось, пороги `passes_quality()` не
трогались, тайлы не перекачивались. Инференс везде выполнялся через
**ONNX Runtime + CUDAExecutionProvider** (боевой контейнер
`pikurr-system-etl-1`, модель `two_opset13.onnx`, по итогам раунда 7).

Контекст (разведка, предшествовавшая этому раунду): визуальный осмотр листа
`N-35-10-А-а-2` показал сплошную сине-серую дымку и размытость в исходных
спутниковых тайлах при явно лесной текстуре. Предсказание модели на этом
листе — 85.2% MEADOW, 10.25% FOREST, то есть модель обманута аномальным
цветовым балансом. Проверка `passes_quality()` в `src/tasks/download.py`
такие тайлы пропускает: она ловит только полностью монохромные
тайлы-заглушки (`gray_ratio` — доля пикселей с `R==G`), а не резкость или
цветовой баланс.

## Задача 1: детектор `is_green` на большой выборке

**Метод**: по 5 тайлов из середины каждого из 906 листов (4530 тайлов),
доля `is_green` по формуле из `segmentate.py`
(`is_green = (1.82*G - R - B) > 0`, доля пикселей на тайл).

**Гистограмма** (20 бинов по диапазону [0,1]):

```
[0.00-0.05): 610 ################
[0.05-0.10): 171 ####
[0.10-0.15): 128 ###
[0.15-0.20):  99 ##
[0.20-0.25):  95 ##
[0.25-0.30):  89 ##
[0.30-0.35):  74 ##
[0.35-0.40):  88 ##
[0.40-0.45):  78 ##
[0.45-0.50):  46 #
[0.50-0.55):  60 #
[0.55-0.60):  42 #
[0.60-0.65):  55 #
[0.65-0.70):  49 #
[0.70-0.75):  60 #
[0.75-0.80):  79 ##
[0.80-0.85):  94 ##
[0.85-0.90): 174 ####
[0.90-0.95): 273 #######
[0.95-1.00): 2166 ############################################################
```

**Вывод: распределение НЕ бимодальное с чётким провалом.** Это широкое
разреженное плато между двумя пиками (у 0 и у 1), плавно убывающее до
минимума ~0.5 и затем плавно растущее — а не два острых горба с узкой ямой.
Вероятная причина: пятиточечная выборка по всем 906 листам захватывает не
только лес — вода, поля, дороги, застройка тоже дают низкий `is_green` по
легитимным причинам, никак не связанным с дымкой. Метрика путает «не лес» с
«испорченный лес».

По критерию ТЗ («если размазано — детектор не подтверждён, дальше по этой
линии не идти») — **на уровне всего датасета `is_green` не годится как
самостоятельный автоматический классификатор** без привязки к типу покрова.

Контрольная проверка: применение порога 0.5 (примерное дно разреженного
плато) **только к уже известной поражённой группе `N-35-10`** (61 лист) даёт
совпадение 59/61 (97%) с более ранней разведкой (`blue_excess`/`sharpness`).
То есть метрика работает предсказуемо **там, где заранее известно, что
должен быть лес** — но не как универсальный фильтр по всему датасету.

Формальные цифры по порогу 0.5 на всём датасете (приводятся по требованию
ТЗ, но ненадёжны ровно по причине выше): 32.6% тайлов (1478/4530), 32.5%
листов (294/906, лист считается поражённым при >50% тайлов выборки ниже
порога).

## Задача 2: лечится ли дымка цветовой нормализацией

**Метод**: 25 тайлов группы `strict` (+ отдельно 10 тайлов конкретно с
`N-35-10-А-а-2`, для которого точный ответ известен — сплошной лес), 25
`questionable`, 25 `normal` (контроль). Четыре варианта на входе инференса:
без изменений; gray-world (выравнивание средних R/G/B); растяжка по
перцентилям 2–98% на канал; комбинация gray-world + растяжка.

| группа | вариант | FOREST | MEADOW | OTHER |
|---|---|---|---|---|
| N-35-10-А-а-2 (10 тайлов) | без изменений | 16.8% | 73.6% | 9.3% |
| | gray-world | 26.5% | 71.7% | 0.9% |
| | **растяжка 2–98%** | **99.3%** | 0.0% | 0.0% |
| | комбо | 99.3% | 0.0% | 0.0% |
| strict, остальные 24 листа | без изменений | 4.1% | 90.6% | 5.0% |
| | gray-world | 4.4% | 91.3% | 4.1% |
| | **растяжка 2–98%** | **92.2%** | 5.9% | 1.0% |
| | комбо | 92.2% | 5.9% | 1.0% |
| questionable (25 листов) | без изменений | 29.0% | 65.2% | 3.6% |
| | gray-world | 29.0% | 65.3% | 3.7% |
| | растяжка 2–98% | 39.4% | 51.6% | 5.6% |
| | комбо | 39.4% | 51.6% | 5.6% |
| **normal, контроль** (25 листов) | без изменений | 79.1% | 17.2% | 0.6% |
| | gray-world | 79.3% | 16.7% | 0.7% |
| | растяжка 2–98% | 82.9% | 13.4% | 0.6% |
| | комбо | 82.9% | 13.4% | 0.6% |

**Наблюдения** (без выводов о том, что делать — решение за человеком):

- Gray-world сам по себе почти не помогает ни на одной группе.
- Перцентильная растяжка резко меняет результат на `strict`
  (16.8%→99.3% FOREST на эталонном листе, 4.1%→92.2% на остальных `strict`),
  заметно слабее на `questionable` (29.0%→39.4%).
- Комбо не отличается от одной растяжки — эффект gray-world растворяется в
  последующей растяжке.
- **Контрольная группа тоже сдвигается** (79.1%→82.9% FOREST, +3.8 п.п.) —
  растяжка не нейтральна для здоровых тайлов.

## Задача 3: влияние строки `final_mask[mask_is_other_high & ~is_green] = CLS_OTHER`

**Метод**: полная реконструкция `process_trapeze()` (high-res + low-res +
слияние контекста + цветокоррекция, как в `segmentate.py`, файл не менялся)
на 4 листах — маска со строкой (текущее поведение) против маски без неё.

| лист | группа | % изменившихся пикселей | направление | MEADOW со строкой → без |
|---|---|---|---|---|
| N-35-10-А-а-2 | strict | 1.06% | 99.4% OTHER→MEADOW | 85.23% → 86.29% |
| N-35-10-Б-в-1 | strict | 3.67% | 99.9% OTHER→MEADOW | 82.61% → 86.28% |
| N-35-33-Б-б-3 | questionable | 1.49% | 80.8% OTHER→MEADOW | 38.49% → 39.69% |
| N-35-12-Г-а-3 | normal | 0.12% | 61.1% OTHER→MEADOW | 12.99% → 13.06% |

**Это расходится с предварительной гипотезой ТЗ (п.5 «Что уже
установлено»)**: строка НЕ «срабатывает на всей площади» и не «полностью
отменяет двухмасштабную коррекцию» — измеренный эффект небольшой (1–3.7%
пикселей на поражённых листах), и FOREST/MEADOW% почти не меняются даже без
неё. Строка лишь возвращает в OTHER небольшую часть пикселей, которые
правило `is_soil` успело отбить обратно в MEADOW. Основной вклад в ложные
85% MEADOW на `N-35-10-А-а-2` даёт сама сеть на этапе high-res/low-res
предсказания — это подтверждает п.4 гипотезы ТЗ («MEADOW порождает сама
сеть»), но опровергает масштаб эффекта из п.5.

## Задача 4: географическая привязка к сценам мозаики

**Важное уточнение**: в процессе работы над этим разделом был получен
ошибочный промежуточный вывод, что сервис `geodzz.by` недоступен (`403` от
`curl` — и с сервера, и с `Referer`). Пользователь показал, что при ручной
проверке с правильным `User-Agent` браузера сервис отвечает `200`.
Перепроверка с сервера с тем же `User-Agent` подтвердила: **сервис работает**,
дело было в отсутствии `User-Agent` у голого `curl`-запроса (тот же паттерн
уже учтён в `download.py` — там `User-Agent` браузера задан).

С рабочими заголовками `.../ImageServer/query?where=1=1&f=json` вернул
**всего 6 записей** — это контуры **целых областей** Беларуси
(`Tag: "Dataset"`: `Brestskaya_obl_all`, `Gomelskaya_obl_all`,
`Minskaya_obl_all`, `Vitebskaya_obl_all_new`, `Grodnenskaya_obl_all_new`,
`Mogilevskaya_obl_all`), без полей с номером тура или датой залёта.

Проверка на 8 листах (4 поражённых из групп `strict`/`questionable`, 4
здоровых) через point-in-polygon: **все восемь листов попадают в одну и ту
же Витебскую область** — на этом уровне детализации каталог принципиально
не различает поражённые и здоровые листы, они административно неразличимы.

**Вывод: географическая привязка к конкретной сцене/туру через этот
эндпоинт недостижима** — публично доступный `ImageServer` не экспонирует
отдельные сцены с датой съёмки, только агрегированные областные контуры.
Дальше эта линия не продолжалась (по ТЗ — не изобретать обходных путей).
Если продолжать — нужно искать другой ресурс/параметр у geodzz (возможно,
отдельный слой сцен вне `Belarus_Web_Mercator_new/ImageServer`), либо
принять, что претензию по качеству придётся формулировать списком
листов/координат, а не списком сцен.
