## Блок B. Проверки должны ходить туда же, куда фронтенд

### B1. `healthcheck.py` — проверка по реальным URL

`REPIKURR/healthcheck.py` дополнен функцией `check_gwc_layers`: она НЕ
собирает URL вручную, а читает `REPIKURR/tools/smoke/captured_gwc_urls.json`
— файл, который теперь пишет сам `smoke.mjs` (доработан этим блоком:
захватывает первый увиденный запрос к `/geoserver/gwc/service/wms` для
каждого кэшируемого слоя, сохраняет как JSON). `bbox` в захваченном URL
заменяется на заведомо непустой тайл из `tiles_with_data.json` (правило
непустых тайлов — случайный/панорамный bbox из живой сессии браузера
непредсказуем по содержимому), все остальные параметры (`layers` с
префиксом workspace, `tiled=true`, `version`, `format` и т.д.) —
дословно те, что реально ушли с фронтенда. Тело ответа разбирается
(PNG-сигнатура + минимальный размер + текст `Unknown layer`/`GWC Error`)
— не только код.

Прогон против прода (после раскатки блока A round34, слой уже
исправен):
```
gwc_layer[pikurr:fields_latest]    True  HTTP 200, PNG, 48272 байт, geowebcache-cache-result=HIT
gwc_layer[pikurr:image_assessment] True  HTTP 200, PNG, 10390 байт, geowebcache-cache-result=HIT
```

Побочно найдена и исправлена проблема деплоя: `healthcheck.py`
обычно копируется на VPS/эмулятор ОТДЕЛЬНЫМ файлом (не всем деревом
`PIKURR_REFACTOR/`), поэтому жёстко прошитый относительный путь до
`docs/round32_assets/tiles_with_data.json` там не существует —
добавлены переменные окружения `TILES_WITH_DATA_PATH` и
`CAPTURED_GWC_URLS_PATH` с понятной ошибкой вместо падения, если файлы
не найдены.

### B2. Проверка фактом: ломаем слой на эмуляторе

Обнаружено попутно: фронтенд на эмуляторе был **не синхронизирован** с
фиксом round34 (`constants.js` там до сих пор без `GWC_CACHED_LAYERS`,
`MapView.jsx` — с голым `layers={rasterLayer}`) — синхронизирован
этим блоком (`rsync REPIKURR/repikurr/src/` → эмулятор), пересобран,
проверено smoke.mjs (9/9). Заодно доустановлены Node 20 и Playwright
на эмуляторе (были в apt только Node 18, Playwright требует 20+) —
инфраструктура для будущих раундов, оставлена (не удалялась).

Прогон по шагам (все — эмулятор, `http://localhost`):

| шаг | действие | smoke.mjs | healthcheck.py (`gwc_layer[...]`) |
|---|---|---|---|
| 1 | база (фикс round34 синхронизирован) | 9/9 | `True`, HTTP 200 |
| 2 | `layers={rasterFqName}` → `layers={rasterLayer}` в `MapView.jsx`, пересборка | 6/9 (4a/6/7 упали) | **`False`, HTTP 400 `GWC Error: Unknown layer image_assessment`** |
| 3 | правка отменена (`rsync` из репозитория), пересборка | 9/9 | `True`, HTTP 200 |

**Подтверждено фактом**: `healthcheck.py` краснеет на той же поломке,
что было в round34, и зеленеет обратно после отмены — цепочка
`smoke.mjs` (перехватывает реальный URL) → `healthcheck.py`
(переигрывает его структуру напрямую, без браузера) работает как
задумано. Важная оговорка о механизме (честно, не подгонка): здоровье
`healthcheck.py` соответствует ПОСЛЕДНЕМУ прогону `smoke.mjs`, не
живому фронтенду в реальном времени — если фронтенд-регрессия
произойдёт МЕЖДУ прогонами `smoke.mjs`, обычный 5-минутный
`external_healthcheck.sh` её не увидит, пока `smoke.mjs` не
перезапустят и не перезапишут `captured_gwc_urls.json`. Это и есть
причина, почему блок B3 делает `smoke.mjs` частью самой выкатки — тогда
`captured_gwc_urls.json` обновляется именно в момент, когда риск
регрессии максимален.

### B3. Дымовой сценарий — обязательная часть выкатки

Выбор: **скрипт выкатки сам вызывает `smoke.mjs`**, не отдельный шаг в
инструкции. Инструкция полагается на то, что оператор (человек или
будущая сессия) прочитает и не забудет последний пункт — именно так
слой оставался сломанным между round32 и round34, хотя дымовая
проверка теоретически была «обязательна» по формулировке CLAUDE.md уже
с round33. Скрипт технически не даёт считать деплой успешным (код
возврата 1) без зелёного прогона.

Добавлен `REPIKURR/deploy_frontend_vps.sh` — формализует
последовательность round34 (`docker build` → бэкап тега на VPS →
`docker save | gzip | scp | docker load` → retag →
`up -d --force-recreate react-client`), затем **обязательно** прогоняет
`tools/smoke/smoke.mjs` против только что раскатанного домена; при
красном прогоне явно печатает, что деплой не считается завершённым, и
готовую команду отката (сам не откатывает — решение за оператором).
Синтаксис проверен (`bash -n`), **на VPS в этом раунде не запускался**
— раскатывать нечего, фронтенд не менялся со времени round34 (правило
«Не делать»: никаких изменений фронтенда на бой сверх блока B, а он
весь — про эмулятор).
