### A3. Смена года при выбранной группе — было подтверждено сломано, исправлено

Факт: `Sidebar.jsx` вызывает **голый** `setSelectedYear()` по `onChange`
селектора года — никакого запроса на пересчёт `bbox`/`stats` он не
запускает (они обновляются только внутри `handleSelectUser`/
`handleSelectOblast`, вызываемых явным выбором района/области/
землепользователя). Смена года при уже выбранной группе оставляла бы
старые числа/охват от предыдущего года.

Исправлено — `useEffect(() => {...}, [selectedYear])` в `App.jsx`,
пересчитывающий `bbox`/`stats` для текущей активной группы. Реагирует
**только** на `selectedYear` (не на группу — иначе задвоил бы вызовы,
которые уже делают `handleSelectUser`/`handleSelectOblast`).

## Блок B. Пустой результат `vec:Bounds`

### B1. Витрина и плагин: карта не двигается, баннер — сделано

`geoserver.js::getBboxByUser()` теперь возвращает `null`, если
`maxx < minx` или `maxy < miny` (вырожденный охват, реальный ответ
GeoServer на пустую выборку — round49). Все три места `setBbox(b)` в
`App.jsx` обёрнуты в `if (b)` — при `null` карта не трогается.
Баннер «нет данных» — существующий механизм `groupEmpty` (round37,
независимый запрос `getFeatureCount`) — typeName там уже учитывает год
правильно (через `fieldsTypeName`), отдельной правки не потребовалось.

Плагин — та же защита в `pikurr.py::_update_bounds()`: при
`upper[0] < lower[0]` или `upper[1] < lower[1]` — карта не двигается,
статус-сообщение «нет данных», без исключения. `_update_stats()` —
явное сообщение при пустом `AggregationResults` (таблица и раньше не
падала, просто была пустой без пояснения).

### B2. Плагин, год без данных — сделано, шаг E2E добавлен

`test_plugin_e2e.py`, новый шаг **B2**: программно добавлен пункт
"2024" в `yearCombo` (реально этого года на проде нет), выбран через
реальную Qt-навигацию, землепользователь уже выбран заранее:
```
[PASS] B2. Год без данных (2024): таблица пуста, карта не сдвинута, без исключений
      строк_таблицы=0, охват_совпадает=True
```

### B3. Витрина, тот же случай — сделано (тестом функции)

Попытка через полный Playwright UI-сценарий (`round50_year_check.mjs`)
дала путаницу состояний (несовпадение мокнутых `districtsByYear` с
реальными районами прода привело к тому, что `Sidebar` сбросил
выбранный район раньше, чем ожидалось, — баннер не успел проверенно
отрендериться за отведённое время). Не стал донастраивать этот
конкретный сценарий дальше — вместо этого протестировал **саму
функцию** напрямую (ТЗ прямо разрешает "тестом функции или через
Playwright"), что даёт чистый и однозначный результат:

`REPIKURR/tools/smoke/round50_bbox_null_check.mjs` (локальный шаблон
из репозитория — на проде ещё старая версия шаблонов, — реальный
прод-GeoServer):
```

Реальный землепользователь, year=2024 (не существует): null
PASS: getBboxByUser() корректно различает пустой и непустой результат
```
