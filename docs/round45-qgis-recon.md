**Точка входа**: `__init__.py:classFactory(iface)` → `pikurr.py:pikurr`.
`initGui()` добавляет один пункт меню/тулбара, `run()` — вся логика.

**B.2. Функции плагина (по коду, `pikurr.py`):**

1. **Автопоиск GeoServer** (`get_geoserver_url`, строки 195-214) —
   пробует `http://localhost:8080`, затем `http://geobotany.xyz`
   (закомментирован более ранний вариант — IP `158.160.183.235:8080`).
2. **Список районов/землепользователей** (`run`, строки 226-281) —
   WPS-запрос `gs:Query` к слою `pikurr:levelsagg`, агрегирующий districts
   (`rn`) и землепользователей (`usname`/`usern_co`), заполняет
   выпадающие списки диалога.
3. **Переключение подложки** (`radio_esri`/`radio_osm`/`base_map`,
   строки 300-345) — добавляет XYZ-слой Esri World Imagery или OSM как
   растровый слой QGIS.
4. **Базовый растровый слой оценки** (`radio_base`, строки 347-365) —
   добавляет `pikurr:image_assessment` через обычный `/geoserver/wms`
   (не через GWC — плагин вообще не использует GWC-эндпоинт, только
   прямой WMS, поэтому не выигрывает от серверного кэша и не подвержен
   ограничениям GWC round37, но и не оптимален по нагрузке на сервер).
5. **Подсветка полей выбранного землепользователя** (`add_vec2`,
   строки 372-441) — добавляет `fields` через `/geoserver/pikurr/wms`
   с `CQL_FILTER=nr_user LIKE '<код>%'`, зумит на bbox через
   WPS-запрос (`demowps4.xml`).
6. **Сводная таблица площадей по сценариям** (`add_vec2`, строки
   442-484) — второй WPS-запрос (`demowps5.xml`, aggregation) даёт
   количество/площадь по сценариям (`meadow`/`forest`/`clearing`/
   `tillage`), рисует HTML-таблицу в `QTextBrowser`.

**B.3. Ключевой вопрос — что из этого QGIS не умеет сам:**

| функция | замена штатными средствами QGIS |
|---|---|
| Подключение к WMS/WFS слоям сервера | **Да** — «Добавить слой WMS/WFS», штатный диалог подключения, ничем не хуже. Плагин просто делает это программно за пользователя. |
| Переключение базовой подложки (Esri/OSM) | **Да** — штатные XYZ-соединения (в QGIS 3.x есть готовые пресеты OSM в «Обзор» → «XYZ Tiles», Esri добавляется вручную тем же способом, что и плагин) |
| Фильтр полей по землепользователю (`CQL_FILTER`) | **Да** — «Свойства слоя → Источник → Построитель запроса» (Query Builder) для WFS/WMS слоя, либо серверный фильтр в URL соединения. Требует знать код `nr_user`, но это верно и для плагина — тот же код берётся из того же списка. |
| Зум на bbox выбранного объекта | **Да** — штатное «Приблизить к выделенным объектам» после фильтрации |
| **Список районов/землепользователей одним готовым выпадающим списком** | **Нет прямой замены** — это единственная функция, для которой штатных средств QGIS не хватает: пользователю пришлось бы вручную писать `CQL_FILTER` с точным кодом, не видя человекочитаемого справочника «кто есть кто». Правдоподобная альтернатива — не плагин, а готовый слой-справочник (WFS `pikurr:levelsagg`/`fields_latest` с атрибутами `usname`/`usern_co`), который можно открыть как обычную таблицу атрибутов и отфильтровать штатным Query Builder. |
| **Агрегированная таблица площадей по сценариям** | **Частично** — QGIS умеет то же самое штатно (Field Calculator + Statistics Panel по отфильтрованному слою), но не в один клик и не в текущем виде HTML-таблицы — это единственная область, где плагин даёт готовый, а не собираемый вручную результат. |

Итог: **5 из 6 функций дублируют штатные возможности QGIS**, разница —
удобство одного клика вместо нескольких. Уникальны (частично) только
готовый справочник землепользователей и готовая сводная таблица.

**B.4. Зависимости.**
- `requests` — внешняя PyPI-библиотека, не входит в ядро QGIS API,
  но фактически доступна в большинстве дистрибутивов QGIS (Windows
  OSGeo4W-сборка, Linux-пакеты — включают её как транзитивную
  зависимость других модулей). Не гарантировано на 100% для любой
  установки.
- **`resources.py` жёстко импортирует `from PyQt5 import QtCore`**
  напрямую (строка 9), в обход штатной абстракции `qgis.PyQt`, которую
  использует весь остальной код плагина (`pikurr.py`,
  `pikurr_dialog.py`). Комментарий в файле — «Created by: The Resource
  Compiler for PyQt5 (Qt v5.12.8)» — сгенерировано в 2024/2025 году под
  Qt5. Официальные сборки QGIS.org для Windows/macOS начиная с 3.40
  переходят на Qt6/PyQt6 — на такой сборке `resources.py` **сломается
  при импорте** (`ModuleNotFoundError: No module named 'PyQt5'`), даже
  если остальной код плагина Qt6-совместим через `qgis.PyQt`. Это
  реальный, конкретный риск совместимости, не гипотетический.
- `qgisMinimumVersion=3.0` в `metadata.txt`, верхней границы нет.
- Остальные используемые PyQGIS API (`QgsProject`, `QgsRasterLayer`,
  `QgsCoordinateTransform`, `QgsLayerTreeLayer`, `QgsRectangle`) —
  стабильные, не deprecated, штатно доступны и на Qt6-сборках через
  `qgis.PyQt`.

файла в обычном GUI QGIS — это не 100% визуальная проверка глазами
человека, но выше, чем «просто прочитали код».

**Трудозатраты**: файл собран и проверен за один присест этого раунда
(~30 минут, включая написание тестового скрипта для QGIS). Сопровождать

## Блок G. z8 в диапазоне засева

**G.1. Расчёт `tile_math`.** Bbox слоёв взят из `GetCapabilities`
(`EX_GeographicBoundingBox`, `CRS:84`), переведён в EPSG:3857.
`tile_range_for_bbox_3857` на z8: **4×3 = 12 тайлов** на слой по
приближённой bbox из публичных capabilities (в пределах ожидания ТЗ
«7-12 на слой»).

**G.2. Контролируемый прогрев (не через `deliver.py` — через
`gwc_http_seed.py`, чтобы не трогать боевую доставку) z8 для обоих
слоёв, реальными HTTP GetMap-запросами:**
```
pikurr:fields_latest      z8: 12 тайлов, 12 hit/0 miss, 1.2с
pikurr:image_assessment   z8: 12 тайлов, 8 hit/4 miss, 5.7с (первый прогон)
```
Часть тайлов уже была в кэше (`hit`) до целевого засева — то есть z8
**уже частично прогревается органическим трафиком браузеров** (что и
показал round44: z8 — второе место по частоте запросов в
`smoke.mjs`), несмотря на то что z8 вне штатного диапазона засева. Это
значит: после каждой доставки (которая truncate'ит GWC) z8 всё равно
остаётся холодным до первого реального визита — ровно тот же паттерн,
который round44 исправил для z9.

Сверка с диском на VPS (`docker exec` в `pikurr_vps_geoserver`, путь
`/opt/geoserver/data_dir/gwc/pikurr_<слой>/EPSG_900913_08/`):
`fields_latest` — **12 файлов** (точное совпадение с расчётом);
`image_assessment` — **15 файлов** (на 3 больше расчёта — реальный
`nativeBoundingBox` слоя в GWC чуть шире, чем округлённый
`EX_GeographicBoundingBox` из публичных `GetCapabilities`, использованный
для приближённого расчёта; авторитетный метод, которым пользуется сам
`deliver.py`, — REST `nativeBoundingBox`, не публичный WMS capabilities;
расхождение в 3 тайла на низком зуме ожидаемо и не является
недосевом). Суммарно добавление z8 **обошлось в ~7 секунд на оба слоя**
— однозначно дёшево.

Ожидаемое предупреждение «доля мелких/пустых тайлов >20%» сработало
(25% и 50% на z8) — при таком широком охвате на тайл (весь регион
данных в 12-15 тайлах) значительная доля площади тайла — фон без
данных, это ожидаемо на низких зумах и не признак поломки (согласуется
с round44 «порог подобран, чтобы не шуметь на малых z9/z10» — на z8 он
всё же шумит, это тише, чем реальная проблема, а не сигнал остановки).

**G.3. HIT после засева** — контрольный повторный проход (без `--resume`,
свежий лог) дал **12/12 hit** для обоих слоёв — устойчиво прогрето.

**G.4. Применить `GWC_SEED_ZOOM_START=8` на VPS — НЕ выполнено.**
Классификатор безопасности среды заблокировал прямую запись на прод
(`sed -i` в `deliver.env` на VPS) как «Remote Shell Writes», несмотря
на явное разрешение этого пункта в задании раунда — эта защита не
осведомлена о содержимом ТЗ и требует явного подтверждения от
пользователя через собственный ввод. Готовая команда (с бэкапом и
откатом), которую нужно выполнить пользователю или одобрить отдельно:
```bash
# на координаторской машине или где есть ssh-доступ к VPS:
TS=$(date +%Y%m%d_%H%M%S)
ssh sgr@158.160.237.90 "cp ~/repikurr/deliver.env ~/repikurr/deliver.env.bak_pre_round45_zoomstart_${TS} && \
  sed -i 's/^GWC_SEED_ZOOM_START=9/GWC_SEED_ZOOM_START=8/' ~/repikurr/deliver.env && \
  grep -n GWC_SEED_ZOOM ~/repikurr/deliver.env"

# откат:
ssh sgr@158.160.237.90 "cp ~/repikurr/deliver.env.bak_pre_round45_zoomstart_<TS> ~/repikurr/deliver.env"
```
Сам факт «дёшево и работает» (G.1-G.3) подтверждён независимо от
применения этой правки — эксперимент выполнен инструментом
`gwc_http_seed.py` напрямую против прод-GeoServer, не через `deliver.env`.

**G.5. `docs/system-state.md`** — не обновлён, поскольку сама правка
конфигурации (G.4) не применена; обновлять документ под неприменённое
изменение не имеет смысла. Обновить разделы 4 и 6 нужно **после** того,
