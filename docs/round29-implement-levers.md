# Раунд 29: внедрение дешёвых правок, затем решение о диске

См. `prompts/PROMPT_implement_levers_round29.md`. Порядок блоков
обязателен: блок A закрывает риск отката на следующей доставке и
выполняется до любой доставки. В этом раунде пользователем разрешены:
правки фронтенда (только блок C), изменения на VPS (только блоки B-D,
каждое — с командой отката).

**Правило замеров**: цифры со стенда, VPS и эмулятора не смешивать,
каждая подписана машиной. **Правило разброса**: сравнительный опыт —
минимум 3 повтора, порядок перемешан, состояние кэша одинаково и
указано.

### A.4. Защита от повторения — `deliver.py` сверяет версию схемы

**Сделано** (`REPIKURR/deliver.py`): новый шаг `check_schema_version`,
выполняется сразу после распаковки пакета, **до любого изменения БД
или растров**. Читает маркер `-- SCHEMA_VERSION = N` из
`create_assessment_schema.sql` внутри пакета (тот же маркер, что уже
был в файле как комментарий — теперь используется программно, не
только для человека) и сравнивает с `SCHEMA_VERSION` в самом
`deliver.py`. Если версия пакета **старше** — `SchemaVersionError` с
понятным текстом, `ok: false`, шаг `check_schema_version` в статусе,
ничего не тронуто. Пакет без этого файла (легаси/assessment-only,
не трогающий схему) — проверка пропускается (`None`), как и раньше.

**Проверка фактом на эмуляторе** (`pikurr-emu`, боевые данные из
блока E round28 уже загружены):
1. Собран тестовый пакет с `SCHEMA_VERSION = 1` (подменён файл в
   валидном реальном пакете) → `deliver.py test_pkg_oldschema.zip`:
   **отказ** на шаге `check_schema_version`
   (`SchemaVersionError: Пакет несёт SCHEMA_VERSION=1, боевая схема
   уже на SCHEMA_VERSION=2...`), статус `ok: false`. Проверено, что
   `agrifields` не тронута — `count(*) = 59209` до и после попытки.
2. Тот же (валидный) пакет с `SCHEMA_VERSION = 2` →
   `deliver.py test_package_current.zip`: **доставка прошла
   полностью успешно** (`=== Доставка завершена успешно ===`,
   healthcheck зелёный).

**Развёрнуто на VPS**: `deliver.py` на `geobotany.of.by` (`~/repikurr/`)
оказался тоже позади — не только без A.4, но и без ВСЕХ фиксов

## Блок B. COG-растры в ETL

### B.1. Место в конвейере

`PIKURR/src/tasks/export.py`, `ExportTask.process_trapeze()` — после
маскирования (наложение маски полей на классифицированный растр,
`merge_imageset` к этому моменту уже отработал раньше в конвейере и
не трогается) записывает обычный `GeoTIFF` тем же профилем, что и
источник; сразу после этого добавлен вызов `_convert_to_cog(out_path)`
— пересобирает записанный файл в COG **на месте**, через временный
файл (`gdal_translate` не пишет поверх своего же источника). Параметры
(`COMPRESS=LZW`, `RESAMPLING=NEAREST`, `BLOCKSIZE=512`) — те же, что
проверены в round28 (категориальные данные — только `nearest`, иначе
появятся несуществующие «смешанные» классы при обзорах). Математика
самой маски и `merge_imageset` не изменены ни строкой.

### B.2. Проверка без потерь

**Найдена и устранена методологическая ошибка по ходу**: первый
прогон `ExportTask` после правки не подхватил новый код — контейнер
ETL не пересобирался (образ строился ДО правки `export.py`), поэтому
файлы остались обычным `GeoTIFF`, а не COG — обнаружено фактом
(`gdalinfo` не показывал `LAYOUT=COG`). После пересборки образа
(`docker compose build etl && docker compose up -d etl`) второй запуск
случайно оказался **два параллельных процесса** одновременно (не
убитый до конца предыдущий фоновый вызов из-за особенности
управления фоновыми задачами в этой сессии) — оба писали в одни и те
же файлы. Обнаружено фактом (`ps aux` в контейнере показал 2 процесса
`ExportTask`), оба остановлены, каталог `2025/` **полностью
восстановлен из бэкапа** `2025_before_cog_backup` (снят ДО первой
попытки) во избежание частично побитых файлов от гонки записи, и
выполнен **один** контролируемый прогон (подтверждено `ps aux` — ровно
один процесс на всё время выполнения).

**Признаки COG подтверждены фактом** (не по имени драйвера — эта
версия GDAL для ЧТЕНИЯ показывает `Driver: GTiff/GeoTIFF` даже для
настоящего COG, COG-драйвер в этой версии только для записи; признак
— метаданные): `gdalinfo` на экспортированном файле показывает
`LAYOUT=COG`, `Block=512x512`, 4 уровня обзоров
(`Overviews: 3072x3584, 1536x1792, 768x896, 384x448`).

**Чек-суммы всех файлов пакета (не выборки из 5)**: `gdalinfo
-checksum` по каждому из **912** файлов, старая (бэкап) версия против
новой (COG) — **TOTAL=912, MISMATCHES=0**. Полное отсутствие потерь
подтверждено на всём объёме, не на образце.
