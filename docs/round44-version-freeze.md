## Блок B. Сверка итога засева с расчётом

### Что сделано

1. `REPIKURR/tools/tile_math.py` дополнен `lonlat_point_to_3857`/
   `bbox_lonlat_to_3857` (перевод `nativeBoundingBox` слоя, который
   GeoServer REST отдаёт в EPSG:4326, в EPSG:3857) — сверено фактом с
   числами round43 (совпадение до 6 значащих цифр).
2. `REPIKURR/deliver.py`: новая `_expected_gwc_tile_count()` — получает
   `nativeBoundingBox` слоя через REST (featuretype для векторного,
   coverage для растрового), считает ожидаемое число тайлов по
   `tile_range_for_bbox_3857` для диапазона `GWC_SEED_ZOOM_START..STOP`.
   `_annotate_seed_shortfall()` сравнивает с фактическим числом файлов
   на диске (`result["files"]`) и добавляет `expected_tiles` и (при
   недоборе сверх порога) `shortfall_warning` в результат — вызывается
   на ВСЕХ трёх путях завершения `_seed_gwc_layer` (стабильность диска,
   пустой список задач GWC, таймаут). Доставку не останавливает ни в
   одном случае (`ok` не меняется).
3. Порог: `> 10%` И `> 3` тайлов одновременно (оба env-параметризуемы:
   `GWC_SEED_SHORTFALL_WARN_PCT`, `GWC_SEED_SHORTFALL_WARN_MIN_TILES`).
   Обоснование — round43 показал точное совпадение (0%) факта с
   расчётом на z10-z12 в норме, поэтому порог не "терпимость к
   обычному шуму", а защита от двух источников ложных тревог: (а)
   легитимный пропуск метатайла на краю bbox (см. CLAUDE.md, комментарий
   round36/D про ~7.5% от ЦЕЛИ GWC — другая база сравнения, но тот же
   класс эффекта) и (б) малое абсолютное число тайлов на z9/z10, где
   один пропущенный крайний тайл даёт крупный процент.
4. `REPIKURR/tools/tile_math.py` добавлен в `SUPPORT_FILES`
   `deploy_backend_vps.sh` (deliver.py теперь его импортирует — на
   плоском VPS-развёртывании файла не было).

### Проверка фактом (VPS, изолированный вызов функций deliver.py, без полной доставки пакета)

Нормальный прогон (`masstruncate` обоих слоёв → `seed_gwc_cache`):
```
fields_latest:     ok=true  seconds=60.4  files=1835 expected_tiles=1835  (без предупреждения)
image_assessment:  ok=true  seconds=76.0  files=1992 expected_tiles=1992  (без предупреждения)
```
Искусственно неполный кэш (после полного засева `fields_latest` удалена
половина поддиректорий z12 — имитация прерванного на середине засева):
```
files=847 expected_tiles=1835
shortfall_warning: "недобор засева: 847/1835 файлов на диске (53.8% меньше расчёта tile_math для z9-12)"
```
После этого — повторный засев восстановил 1835/1835 (точное совпадение,
без предупреждения). Прод-состояние кэша по завершении тестов —
полное (1835/1992 файлов, см. `healthcheck.py`/`smoke.mjs` ниже).

### Вердикт

**Подтверждено.** Нормальная доставка — без предупреждения (точное
совпадение факт/расчёт); искусственно неполный засев — предупреждение
с верными числами. Доставка в обоих случаях не прерывается.
