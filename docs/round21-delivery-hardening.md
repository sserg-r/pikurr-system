# Часть A

## A1. Восстановление после сбоя — исправлено

`watchdog.py`: `seen` теперь хранит `(имя, размер, mtime)` вместо только
имени (выбранный вариант — обосновано в отчёте, который отправлял до
реализации: не требует аккуратной синхронизации "удалить из seen только
после реального завершения", устойчиво к параллельной обработке при будущих
изменениях).

**Проверено живым тестом**: битый ZIP → `failed/`; затем валидный пакет с
**тем же именем** положен в `inbox/` без рестарта демона — watchdog
обработал его (попытка доставки видна в журнале с новым таймстампом), а не
проигнорировал молча.

**Побочный инцидент при тестировании**: минимальный тестовый пакет (1 лист)
запустил `_clear_stale_rasters` (round20, задача 2) и унёс 911 настоящих
боевых растров в `_removed_`, прежде чем упасть на отсутствующем
`vectors.gpkg` — тестовый пакет не был «годом целиком», а механика 2 раунда
это предполагает. Заметил немедленно, восстановил (файлы просто перенесены,
не удалены — задача 2 сработала как задумано и это и спасло), проверил
содержимым (912 файлов, 912 гранул, WMS отдаёт прежний растр). Для
дальнейших тестов A2 использовал только полные 912-листовые пакеты.

## A2. GeoWebCache — проверено, защита добавлена

`GET /geoserver/gwc/rest/layers.xml` на сервере вернул `<layers/>` —
**GWC сейчас не кэширует ни один слой**. Добавил защитный код на будущее:
`_truncate_gwc_layer_if_cached()` перед каждым обновлением стора проверяет
`GET .../gwc/rest/layers/{layer}.xml`; если слой зарегистрирован — чистит
через `POST .../gwc/rest/masstruncate`. Сейчас это всегда no-op (404 →
пропуск), подтверждено в живом логе.

**Проверка замены содержимого (главный пункт задачи)**: собрал полный
912-листовой пакет, в котором **один** TIF (уже присутствующий в текущем
индексе) залит одним новым значением через GDAL (с сохранением
георефренцирования — проверил `GetGeoTransform()` до/после, совпадает).
Доставил как обычный пакет. WMS по bbox этого листа: **до** — смесь 5
цветов классификации, **после** — 100% один новый цвет (4096 из 4096
пикселей). Подтверждает: harvest+reset подхватывает изменённое содержимое
при том же имени файла, не только добавление новых гранул — именно тот
случай, который проверка round20 пропустила (там менялся состав, не
содержимое). После проверки вернул исходный файл (передоставил
немодифицированный пакет), сверил: гистограмма и число гранул/файлов
совпадают с состоянием до теста.

## A3. Подсчёт гранул без `docker exec` — исправлено

`count_granules_in_index()` читает `.dbf`-индекс напрямую (байты 4-7
заголовка — dBASE-спецификация, little-endian uint32), без `ogrinfo`/`docker
exec`. **Сверено с прежним методом на живых данных: оба дают 912.**
`geoserver_data` смонтирован с хоста, поэтому доступ к `.dbf` не требует
контейнера — `deliver.py` для этой операции больше не нуждается в членстве
хоста в группе `docker`.

## A4. Гонка двух экземпляров watchdog — исправлено

`fcntl.flock` на `watchdog.lock`, неблокирующий режим. **Проверено живым
тестом**: попытка запустить второй экземпляр вручную завершилась немедленно
с `ERROR Уже запущен другой экземпляр watchdog (pid <N>) — выхожу` —
корректно называет PID владельца.

## A5. Накопление служебных каталогов — реализовано

`deliver.py --cleanup [--dry-run] [--retention-days N]` (по умолчанию —
`DELIVERY_RETENTION_DAYS` или 30). Убирает `data/geodata/_removed_*/`
(по дате в имени каталога) и `status/*.json`, `failed/*.zip` (по mtime).
**Проверено на сервере**: с retention=30 сейчас находит 0 объектов (всё
свежее), с retention=0 корректно находит все 3 существующих служебных
объекта; `--dry-run` подтверждённо ничего не удаляет (проверил `ls` после).
Само по расписанию не запускается — это ручной/cron-вызов, не встроенный
таймер (не входило в объём задачи).

# Часть B — подготовлено, не выкатывалось

## B1. Учётные данные по умолчанию

- `deliver.py`: `FRONTEND_DB_PASSWORD` и `GEOSERVER_PASSWORD` больше не
  имеют дефолтов — `_required_env()` бросает `RuntimeError` с понятным
  текстом при отсутствии переменной (падает при импорте модуля, то есть
  сразу при старте, а не на середине доставки).
  **Замечание**: это затрагивает и `--cleanup` — он тоже требует эти
  переменные, хотя они ему не нужны (модульный уровень проверки не разделяет
  режимы). Не критично на практике (`deliver.env` грузится всегда), но
  стоит иметь в виду при автоматизации `--cleanup` через cron без загрузки
  `deliver.env`.
- `docker-compose.server.yml`: `POSTGRES_PASSWORD`/`GEOSERVER_ADMIN_PASSWORD`

- `.gitignore`: добавлен `REPIKURR/geoserver_data/security/usergroup/default/users.xml`

## B2. Сетевая конфигурация

`REPIKURR/docker-compose.vps.yml` (новый файл, `server.yml` не трогал):
PostGIS и GeoServer — `127.0.0.1`-only порты (не убрал совсем — `deliver.py`
работает на самом VPS-хосте как обычный процесс и стучится в них через
`localhost`; полное отсутствие портов сломало бы доставку, не только
внешний доступ — уточнение к буквальному чтению ТЗ). nginx — единственная
публичная точка (`REPIKURR/nginx.vps.conf.template`, envsubst по `${DOMAIN}`):
TLS, редирект 80→443, HSTS/`X-Content-Type-Options`/`X-Frame-Options`,
админка и REST GeoServer под basic-auth, WMS/WFS/WMTS публичны. Certbot —
отдельный сервис, webroot-режим, автопродление раз в 12 часов.

Окно недоступности при переиндексации (14-15с, замер round20) описано;
предложено (не реализовано) staging-каталог для будущего сокращения этого
окна почти до нуля — см. документ.

## B3. Канал доставки — предложение

Диспетчер-скрипт на одном ограниченном ключе, разбирающий
`SSH_ORIGINAL_COMMAND` и пускающий ровно два паттерна: `rsync --server...`
(через `rrsync -wo`, ограничивает запись каталогом `inbox/`) и
`cat .../status/pikurr_update_*.zip.json` (без переменных путей — только
фиксированный каталог + маска). Это отдельно решает конфликт, на который
указывало ТЗ: `command=` в `authorized_keys` разрешает ровно одну команду, а
`PushTask` использует ssh дважды по-разному (`rsync` и опрос статуса) — без
диспетчера они не совмещаются одним ограниченным ключом. Второй, более
явный для аудита вариант (два раздельных ключа) описан и отклонён — сложнее
без явной выгоды. Код `push.py` не менял — только текст в документации.
